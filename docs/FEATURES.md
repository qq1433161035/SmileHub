# SmileHub 功能说明

按“用户能用到什么”来写，关键参数与阈值一并列出；代码结构与维护见
[MAINTENANCE.md](./MAINTENANCE.md)。

演示视频（B 站）：[对开源项目的二次封装](https://www.bilibili.com/video/BV1tKnp6FE7n)

## 1. 四个页面

| 页面 | 作用 |
| --- | --- |
| 个人信息 | 账号、积分、调用记录 |
| API | 本地 OpenAI 兼容网关与悬浮窗 |
| 对话 | 内置 Agent，可读写文件、跑命令、做逆向 |
| 设置 | 工具执行、上下文压缩、权限、ADB、目录 |

## 2. 账号与凭证

- **双区域**：国内版与国际版是两套独立账号体系，可同时各登录一个，随时切换，切换即时生效。
- **多账号**：同一区域可保存多个账号，列表里标注“使用中”，可单独删除。
- **OAuth 登录**：走官方 CLI 的授权流程，登录一次后长期使用。
- **Token 自动刷新**：过期前自动续期，失败时保留旧 token 并提示。
- **凭证查看**：点开当前账号可查看完整 Access/Refresh Token、过期时间，并支持一键复制。
- **签到与积分**：个人信息页可签到、查看积分余额与有效期。
- **调用记录**：记录每次转发的模型、Tokens、积分消耗，并汇总到账号维度；默认不加载，点按钮才读取。

## 3. 本地 API 网关（API 页）

- **协议**：
  - `GET /v1/models`
  - `POST /v1/chat/completions`（OpenAI Chat Completions）
  - `POST /v1/messages`（Anthropic Messages，开关控制）
  - `POST /v1/responses`（OpenAI Responses，开关控制）
  - `GET /healthz`
- **流式透传**：SSE 原样转发；客户端要求非流式时可聚合成一次性响应。
- **身份伪装**：可改写客户端自报的系统提示，避免上游按客户端身份拒绝。
- **访问控制**：
  - 默认只监听 `127.0.0.1`，每个请求都要带本机密钥
  - 可开启“局域网访问”，监听 `0.0.0.0`，用单独的局域网密钥鉴权
  - 局域网请求会记录来源 IP，本机请求不记录
- **HTTPS**：可在 `端口 + 1` 额外提供 TLS 版本，使用应用自签的本地 CA。
- **悬浮窗**：
  - 运行时可显示状态面板，让进程保持“可见”，避免被系统冻结
  - 支持拖动、透明度、圆点模式（不拦截点击）、防烧屏位移
  - 高级设置里可单独关闭悬浮窗，通知栏状态仍保留
- **高级设置**：非流式聚合、Anthropic 格式、Responses 格式、HTTPS、身份伪装、悬浮窗开关、调用记录上限。

## 4. 内置 Agent（对话页）

Agent 不是“带历史记录的聊天框”，而是一个能连续调用工具、观察结果、再决策的
循环：每轮把当前 transcript 和工具定义发给模型，收到 `tool_calls` 就执行，
把结果作为 `tool` 消息追加回去，直到模型不再调用工具或用完轮次上限。

### 4.1 多模态

**发送图片（用户 → 模型）**

- 输入框左侧的图片按钮打开系统相册（仅图片），选中后显示 48dp 预览，可点叉移除。
- 图片在发送前只保存在内存中，不写进会话文件；应用被杀就丢失，这是有意的。
- 发送时统一处理：最长边缩放到 1568px（小图不放大），JPEG 质量 85，Base64 编码为
  `data:image/jpeg;base64,...`，作为用户消息的附件随文本一起发出。
- 同一轮只带一张图；下一次不带图的消息不会重复携带旧图。

**按路径看图（工具 → 模型）**

- 模型随时可以调用 `view_image`，参数就是相对工作区或绝对路径，支持 png/jpg/webp。
- 工具读取并解码图片，套用同样的 1568px / JPEG 85 规则，把图片附加到下一段上下文里。
- 返回给模型的文本包含原始尺寸（如 `1920x1080`），方便它判断是否需要进一步裁剪。
- 文件不存在、不是图片、是目录，都会返回明确的错误文本，而不是让模型猜。
- 这条链路存在的意义：`read` 或 `bash` 读图片只会得到二进制乱码，模型必须先
  “看”到图，才能回答“这个界面哪里有问题”。

**权限**：`view_image` 与 `read` 同属只读工具，在“自动判断”模式下不需要确认。

### 4.2 多会话并发

- 每个会话是一份独立状态：transcript、模型选择、思考强度、上下文窗口、审批模式、
  轮次上限、压缩进度、待发送图片，互不共享。
- **同会话串行**：一个会话正在运行时，再次发送会被忽略（发送键不可用），
  避免两条流同时写同一份记录。
- **跨会话并行**：会话 A 跑长任务（例如解码 APK）时，切到会话 B 发消息互不阻塞；
  切回 A 能看到它继续产出的内容。
- **输出隔离**：后台会话的事件只写自己的记录，不会串到当前屏幕。
- 会话切换器显示“已压缩”标记，可新建、切换、删除；删除会同时清掉它的归档目录。
- 落盘时机：每次工具调用结束、出错、压缩和退出时保存，进程被杀后能恢复到
  最后一次保存点。

### 4.3 模型与推理参数

- 模型列表来自网关的 `/v1/models`，按厂商着色显示。
- 输入框上方一行可横向滚动：模型、思考强度、上下文窗口。
- **思考强度**：仅在模型支持时出现，含“不思考”；按所选档位传给上游。
- **上下文窗口**：选 0 表示交给服务端默认，选具体值才参与本地压缩预算计算。
- 三项选择都会持久化；刷新模型列表不会重置，只有模型确实不存在时才回退到第一个。

### 4.4 运行控制

- **停止按钮**：运行中发送键变成停止键。点击会立刻断开在途 HTTP 连接
  （读阻塞时只有 disconnect 能解开），循环在下一个检查点退出，已输出内容保留。
- **审批模式**：
  - 允许所有：不询问，直接执行
  - 自动判断（默认）：`read`、`view_image` 自动放行，写入、命令、下载、安装等询问
  - 每次询问：所有工具调用都要确认
- **审批内容按参数生成**，例如 `bash` 显示的是具体命令而不是工具名，
  `apk_install` 会标明“卸载后安装（会清除应用数据）”。
- **审批弹窗**只能点“允许”或“拒绝”关闭，点空白或按返回键不会被当成拒绝。
- **轮次上限**：1–1000，默认 100。默认值刻意设高，因为一次逆向任务可能包含
  解码、改 smali、构建、签名、安装几十次往返；上限只用于兜底防止死循环。

### 4.5 上下文压缩

按“先落盘、再摘要”两级处理，避免一上来就丢信息：

- **预算估算**：不引入 tokenizer，按字符类型保守估算——ASCII 约 4 字符/token，
  中文约 1.6 字符/token，每条消息再加 8 的固定开销；工具定义每轮全量发送，
  单独计入固定成本。
- **默认预算**：用户没选窗口时按 128k 计算；超过 70% 触发压缩，目标压到 45%。
- **第一级：工具输出落盘**：超过 32000 字符的旧工具结果写入归档文件，会话里
  只留 `[tool output offloaded]` 占位符与路径；最近 3 条工具结果始终保留原文。
- **第二级：摘要旧轮次**：仍超预算时，从最老的用户轮次开始摘要，至少保留最近
  6 个轮次的原文；摘要上限 900 tokens，以 `[历史摘要]` 前缀插回。
- **按轮次分组**：以 `user` 消息为界切分，保证 `assistant(tool_calls)` 与随后的
  `tool` 消息落在同一组，压缩不会破坏协议要求的配对关系。
- **可观测**：压缩时推送一条事件（移除了多少条、摘要多少 token、归档路径、
  是否降级为本地截断），也可手动点“压缩”。
- 归档在 `agent/sessions/<会话>/` 下，需要时可回查原文。

### 4.6 网络异常处理

- **连接超时 20 秒**；读超时设为 0，因为流式回答的间隔可能很长，不能按普通请求算。
- **不复用连接**：请求显式带 `Connection: close`。上游网关会在空闲后单方面关闭
  keep-alive，复用旧连接就会直接报 `Software caused connection abort`。
- **未产生任何输出时静默重试一次**（间隔 700ms）。此时没有字节进入解析器，
  重试不会重复计费、也不会重复显示。
- **半途断流自动续写**：把已输出的片段作为半条 assistant 消息并入历史，
  再发一条“从中断处继续、不要重复”的提示，只续一次；续写也失败才报错。
- **提示中文化**：超时、DNS 解析失败、连接被中断、TLS 握手失败、其他 IO 异常
  分别给出可操作的中文说明，而不是把英文 errno 丢给用户。
- **不重复提问**：失败的一轮不会把用户消息留在历史里；如果末尾已存在完全相同的
  用户消息则复用，修复旧会话里重复消息的问题。

## 5. Agent 工具

### 5.1 内置工具

| 工具 | 参数 | 行为 |
| --- | --- | --- |
| `read` | `path`、`offset`、`limit` | 按行读取文本，带行号；默认从第 1 行起、最多 2000 行 |
| `write` | `path`、`content` | 整文件覆盖写入，自动创建缺失的父目录 |
| `edit` | `path`、`old_text`、`new_text`、`replace_all` | 精确替换；默认要求原文只出现一次，否则报错 |
| `view_image` | `path` | 读取 png/jpg/webp，缩放到最长边 1568px、JPEG 85 后作为图片交给模型 |
| `bash` | `command`、`timeout_seconds` | 在工作区执行 `sh -c`，开启 root 后改走 `su -c`；合并 stdout/stderr |
| `python` | `code` / `path`、`args`、`timeout_seconds` | 内置 CPython 执行代码或 `.py` 文件；`args` 映射为 `sys.argv` |
| `download` | `url`、`path`、`unzip`、`timeout_seconds` | 下载文件或解压 zip；下载的文件默认可执行 |

补充约定：

- **路径解析**：相对路径基于 Agent 工作区，绝对路径按原样使用；`download` 只允许
  写入工作区或私有工具目录，越界会被拒绝。
- **`download` 的 `tools/` 前缀**：`path` 以 `tools/` 开头时写到应用私有目录
  （唯一能执行下载 ELF 的地方），其余写到 `/sdcard/WBHub/` 工作区。
  解压带 Zip Slip 防护，条目落到目标目录之外会被跳过。
- **`python` 查找顺序**：`path` 优先于 `code`；`sys.path` 依次加入私有目录与工作区
  的 `py_modules`、`site-packages`；默认超时 60 秒（可设 1–300 秒），输出有长度上限。
- **`bash` 的环境**：`<私有>/bin` 与 `<工作区>/bin` 排在 `PATH` 最前，下载的
  可执行文件可以直接按名字调用；`pm`、`adb`、`screencap` 等在以应用身份运行时会被
  系统拒绝，需要 root 或改用对应专用工具。
- **工具结果长度**：过长时会被截断并注明；超长旧结果在压缩阶段落盘为占位符。

### 5.2 逆向与工程工具

- 工程：`toolchain_status`、`project_import`、`project_list`
- APK：`apk_info`、`apk_decode`、`apk_build`、`apk_align`、`apk_sign`、`apk_verify`、`apk_install`、`apk_uninstall`
- DEX：`dex_list`、`dex_decompile`
- SO：`so_info`、`so_disassemble`
- 应用：`package_info`、`app_list`、`app_permissions`、`app_launch`、`app_stop`、`app_grant`、`app_debug`
- 设备：`logcat`、`adb_status`、`adb_connect`、`adb_shell`

### 5.3 自扩展：缺什么就下载什么

内置工具只覆盖常见路径。真正缺能力时，Agent 可以在运行过程中自己补齐，而不是
回答“不支持”。这是本项目与“固定工具集”最大的区别。

**能下载什么、放到哪、怎么用**

| 下载内容 | 目标位置 | 之后如何调用 |
| --- | --- | --- |
| 可执行文件（busybox、自编译 CLI、静态链接工具） | `download` 的 `path` 写 `tools/bin/<名字>`，实际落在应用私有目录 `files/WBHub/bin/` | `bash` 的 `PATH` 首位，直接按名字执行；下载后自动 `chmod +x` |
| 纯 Python 包（zip / wheel 解包） | `tools/py_modules/` 或 `tools/site-packages/`，配合 `unzip: true` | `python` 工具已把这两个目录加入 `sys.path`，直接 `import` |
| 普通文件、脚本、样本 | `/sdcard/WBHub/` 工作区任意路径 | `read`、`write`、`bash`、`python` 直接使用 |
| 外部工具定义 | `/sdcard/WBHub/tools/<名称>/tool.json` + 入口脚本 | 自动注册为模型可调用的工具，新增或修改后下次调用即生效 |

**为什么可执行文件必须放私有目录**

- Android 10+ 对 `/sdcard` 挂载 `noexec`，下载到那里的 ELF 无法执行；
- 本项目 `targetSdk 28`，应用私有目录允许直接 exec（与 Termux 的做法一致）；
- 所以 `download` 的 `path` 以 `tools/` 开头时会落到 `files/WBHub/`，其余才写
  工作区；两个根目录之外一律拒绝。

**下载后如何被调用**

- **`bash`**：`<私有>/bin` 与 `<工作区>/bin` 排在 `PATH` 最前，下载完可以直接
  `mytool --version`；开启 root 后自动走 `su -c`。
- **`python`**：`sys.path` 依次包含私有目录与工作区的 `py_modules`、`site-packages`，
  zip 解开即可 import，不需要安装 pip。
- **脚本**：`.py` 用 `python { path, args }` 反复调用，支持 `sys.argv` 与 `__file__`；
  `.sh` 用 `bash` 调用。
- **持久化**：文件留在设备上，重启应用后仍在；用户也可以用文件管理器手工投放，
  效果相同。

**注册成原生工具（可选）**

`/sdcard/WBHub/tools/<名称>/tool.json` 可声明 `name`、`description`、`entry`、
`properties`、`required`、`risk`、`root`、`timeout_seconds`、`max_output_bytes`。
入口脚本从 stdin、`WB_ARGS`、`WB_ARG_<NAME>` 三种方式拿到参数，stdout 回给模型，
stderr 作为诊断。应用首次运行会自动生成 `hello` 与 `apk_summary` 两个示例；
自定义工具不能与内置工具重名。

**典型用法**

- “把 jadx CLI 下载到 `tools/bin`，然后反编译这个 APK”
- “把这个 zip 解压到 `tools/py_modules`，再用 python 调用里面的库”
- “缺 ffmpeg 就下载一个 arm64 静态版，转完这段视频”
- “写个 `tool.json` 把这段脚本注册成工具，以后直接调用”

**边界**

- 下载与执行默认都走审批（“自动判断”模式下会询问）；仅支持 http(s)。
- 只能写入工作区或私有目录，zip 解压带 Zip Slip 防护。
- 下载的 ELF 必须是 arm64-v8a、面向 Android bionic 构建；glibc 程序无法运行。
- `ctypes` / `cffi` 被禁用，Python 不能直接加载下载的 `.so`；要反汇编请用内置的
  `so_info` / `so_disassemble`。
- 需要系统特权的操作仍受 Android 权限与 root 状态限制。

## 6. 逆向能力

- **APK 解码 / 回打包**：apktool（定制 2.10.0），支持资源与 smali。
- **资源编译与对齐**：内置 arm64 的 aapt2、zipalign，从 APK 的 native 目录直接执行。
- **签名与校验**：apksig，支持生成/复用签名密钥、验证签名方案。
- **DEX**：smali/baksmali 反汇编与汇编；jadx 反编译为 Java。
- **SO**：纯 Kotlin 解析 ELF 结构；Capstone 反汇编（JNI 封装）。
- **工程工作区**：导入 APK 建立工程，解码产物、构建产物、签名产物分目录管理。
- **安装兜底**：常规安装失败时可用 FileProvider 拉起系统安装器。

## 7. 设备能力

- **ADB 无线调试**：
  - 跳转系统无线调试页
  - 通过通知栏 RemoteInput 输入 6 位配对码（保留系统配对弹窗，不抢焦点）
  - mDNS 自动发现配对/连接端口，配对成功后自动连接
  - 支持“启动时自动连接”，状态显示已连接地址
  - 可重置本地 ADB 密钥
- **root 开关**：开启后 `bash` 与提权工具走 `su`；未开启时以应用身份执行。
- **所有文件访问**：用于读写 `/sdcard` 工作区与外部 APK。
- **应用管理**：列出应用、查看权限、启动/停止、授予/撤销权限、设置调试应用。
- **日志**：按包名或关键字读取 logcat。

## 8. Python 运行时

- APK 内置 CPython 3.12（Chaquopy），无需设备另装解释器。
- 支持两种调用：临时执行一段代码，或执行工作区里的 `.py` 文件（可带参数）。
- 工作目录固定为 Agent 工作区；`py_modules`、`site-packages` 自动加入 `sys.path`。
- 默认超时 60 秒，输出有长度上限；超时后会提示代码可能仍在后台运行。
- `ctypes` / `cffi` 被禁用：加载原生库失败会直接杀进程，需要看 SO 请用 `so_info` / `so_disassemble`。

## 9. 存储与数据

| 内容 | 位置 |
| --- | --- |
| 工作区（可执行扩展、下载、脚本） | `/sdcard/WBHub/` |
| 私有工具目录（`bin`/`py_modules`/`site-packages`/`downloads`） | `/data/data/com.wbhub.app/files/WBHub/` |
| 会话与压缩归档 | `/sdcard/WBHub/agent/sessions/` |
| 调用记录 | `/sdcard/WBHub/records/` |
| 凭据、ADB 密钥、证书、设置 | `/sdcard/WBHub/{credentials,adb,certificates,settings}/` |

会话在每个工具调用结束、出错、压缩和退出时落盘；进程被杀后重新打开应用可恢复到最后一次保存点。

## 10. 已知限制

- 依赖 WorkBuddy 私有接口，上游变更可能导致功能失效。
- 悬浮窗保活取决于系统重要性判定，激进的后台策略下仍可能被限制。
- 内置工具链只打包 arm64-v8a。
- `bash` 的超时会在命令结束（输出读完）后才判断，持续挂起且不输出的命令可能不会
  按时返回；`python` 工具的超时只是不再等待（解释器线程仍在后台），两者都不是真正的
  强制终止。需要硬超时时，可在命令里自行调用 `timeout`。
- 多模态一次只附带一张图；同一轮需要对比多张图时，让模型分别调用 `view_image`。
- 国际版账号可能需要先在官方客户端完成试用激活。
